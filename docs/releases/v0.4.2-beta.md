## Beacon v0.4.2-beta

Workers are no longer an empty “attach a container” label. A worker is a spec Beacon
runs: start command, env vars, Docker image or Dockerfile, CPU/memory, replicas,
restart policy, optional cron, autoscale, autodeploy, and live logs. Native
processes work on Windows without systemd.

Every project page now uses one layout — health, then live logs or preview, then
configuration, then actions. Configuration is grouped into titled bands inside a
single panel (service, how it runs, public address, preview, environment,
resources, scaling, restarts, deploys, notes); each kind shows only the bands that
apply to it, and a worker's advanced bands stay collapsed until you ask for them.

Remove a project with **Remove from dashboard** (unlink, files stay) or **Delete
Beacon files too** (stop and destroy what Beacon created).

### Upgrade from v0.4.1-beta

In the app: **Updates → Beacon** → install **v0.4.2-beta**.

Or on the server:

```bash
export SYSTEMDASH_HOME=/opt/systemdash
bash /opt/systemdash/current/scripts/install-release.sh VikPraet/systemDash v0.4.2-beta
sudo systemctl restart systemdash
```
